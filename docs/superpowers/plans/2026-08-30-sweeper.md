# Expiration Sweeper Implementation Plan

> **Execution mode:** Same as every prior phase — Claude writes each task's failing test (or, for Task 5's `main.go`, the manual verification steps), the user writes all implementation code, Claude reviews before moving on. No exceptions for small config changes (Task 1) — that mistake was made and corrected in Phase 3.

**Goal:** Build the expiration sweeper: a one-shot CLI that deletes expired metadata rows and their S3 objects, in batches, then exits.

**Architecture:** Same interface-seam pattern as the other services — `db.Repo` (Postgres), `storage.Store` (S3/MinIO), `sweep.Run` (the actual loop, depends only on interfaces so it's unit-testable with fakes) — wired in `cmd/sweeper/main.go`. Unlike Write/Read Service, there's no HTTP handler layer and no `/healthz` — this binary runs once and exits, nothing to probe.

**Tech Stack:** Go 1.26 stdlib `database/sql`/`context`, `jackc/pgx/v5`, `aws/aws-sdk-go-v2` — all already dependencies, no new ones.

## Global Constraints

- Module path: `github.com/ah-naf/pastebin`.
- Sweeper is a separate process from Read/Write Service — no code here runs inside either of those binaries.
- One invocation = one sweep pass, then exit. Scheduling (cron/k8s CronJob/local loop) is external, not built here.
- Batches of `batchSize` rows (config: `SWEEPER_BATCH_SIZE`, default `500`), looping until a batch comes back empty.
- Deletion order per row: Postgres metadata row first, then best-effort S3 object delete. A metadata-delete failure skips that row's S3 delete and leaves the row for the next run to retry. An S3-delete failure after a successful metadata delete is logged and NOT retried — accepted as a permanent leak, same tradeoff Write Service already accepts for its own orphaned-object case.
- `FindExpiredBatch` query: `expires_at IS NOT NULL AND expires_at <= now() AND is_deleted = false`, ordered `expires_at ASC`.
- `sweeper/internal/storage.Store` does NOT auto-create the bucket (same reasoning as Read Service).
- Overall run wrapped in a 5-minute timeout in `main.go` — a hung DB/S3 fails the process rather than hanging forever.
- Tests: stdlib `testing` only, table-driven where it fits. Integration tests (Postgres/MinIO) skip cleanly via `t.Skip` when unreachable.

```go
func TestFindExpiredBatchReturnsOnlyExpiredNonDeletedRows(t *testing.T) {
	repo, conn := setupRepo(t)
	past := time.Now().Add(-time.Hour).Truncate(time.Second).UTC()
	future := time.Now().Add(time.Hour).Truncate(time.Second).UTC()

	expiredID := "test-expired-" + t.Name()
	futureID := "test-future-" + t.Name()
	deletedID := "test-deleted-" + t.Name()
	neverExpiresID := "test-never-" + t.Name()

	insertRow(t, conn, expiredID, false, &past)
	insertRow(t, conn, futureID, false, &future)
	insertRow(t, conn, deletedID, true, &past)
	insertRow(t, conn, neverExpiresID, false, nil)

	batch, err := repo.FindExpiredBatch(context.Background(), 100)
	if err != nil {
		t.Fatalf("FindExpiredBatch() returned error: %v", err)

	}

		t.Errorf("future-expiry row %q should not be in batch", futureID)
	}

		t.Errorf("already-deleted row %q should not be in batch", deletedID)
	}
	if found[neverExpiresID] {
		t.Errorf("never-expiring row %q should not be in batch", neverExpiresID)
	}
}
```

```go
	batches       [][]db.ExpiredPaste
	callIndex     int
	deleteErr     map[string]error // paste id -> error to return from DeleteMetadata
	deletedIDs    []string
	findErr       error

func (f *fakeRepo) FindExpiredBatch(ctx context.Context, limit int) ([]db.ExpiredPaste, error) {
```

### Task 5: `sweeper/cmd/sweeper/main.go`

No Go test file — wiring, verified end-to-end against real seeded expired
data, proving the whole binary actually cleans up what it's supposed to.

**Files:**
- Implementation (user writes this): `sweeper/cmd/sweeper/main.go`

**Interfaces:**
- Consumes: `config.Load()` (Task 1's `SweeperBatchSize`), `pgconn.Open`
  (Phase 1), `db.NewRepo`/`storage.NewStore`/`sweep.Run` (Tasks 2-4).
- Produces: a one-shot process that sweeps once and exits.

- [ ] **Step 1: User writes `sweeper/cmd/sweeper/main.go`**

`config.Load()` (fatal on error) → `pgconn.Open(cfg.DatabaseURL)` (fatal
on error) → apply the same bounded pool settings
(`SetMaxOpenConns`/`SetMaxIdleConns`/`SetConnMaxLifetime`) → `ctx,
cancel := context.WithTimeout(context.Background(), 5*time.Minute)` →
`storage.NewStore(ctx, cfg.S3Endpoint, cfg.S3AccessKey, cfg.S3SecretKey,
cfg.S3Bucket, cfg.S3UseSSL)` (fatal on error) → `db.NewRepo(sqlDB)` →
`sweep.Run(ctx, repo, store, cfg.SweeperBatchSize)` → log the result
(`log.Printf("swept %d expired pastes", deleted)`) — if `Run` returned an
error, log it and `os.Exit(1)`; otherwise exit 0 (falling off the end of
`main` is exit 0). No HTTP server, no signal handling, no graceful
shutdown — there's no long-running work to interrupt.

- [ ] **Step 2: Seed expired data and run the sweeper**

The other services never create already-expired pastes (Write Service
only sets future/never expiry), so seed directly with SQL after creating
a real paste through Write Service (so its S3 object actually exists):

```bash
cd infra && docker compose up -d && cd ..

# Create a paste normally (with a short expiry so its shape matches reality)
DATABASE_URL="postgres://pastebin:pastebin_dev_password@localhost:5433/pastebin?sslmode=disable" \
S3_ACCESS_KEY=pastebin_minio S3_SECRET_KEY=pastebin_minio_password \
ID_XOR_SECRET=9f3a1c2e5b7d0f14 \
go run ./write-service/cmd/write-service &

sleep 1
RESP=$(curl -s -X POST http://localhost:8080/paste -d '{"content":"about to expire","expires_in_seconds":3600}')
echo "$RESP"
# extract the id from $RESP, call it <id> below

# Kill write-service, then back-date its expires_at directly (this is the
# only way to get an actually-expired row locally, short of waiting an hour)
docker compose -f infra/docker-compose.yml exec postgres psql -U pastebin -d pastebin \
  -c "UPDATE pastes SET expires_at = now() - interval '1 hour' WHERE paste_id = '<id>';"

# Confirm the object exists in MinIO before sweeping
docker compose -f infra/docker-compose.yml exec minio sh -c \
  "mc alias set local http://localhost:9000 pastebin_minio pastebin_minio_password >/dev/null && mc stat local/pastebin/<id>"

# Now run the sweeper
DATABASE_URL="postgres://pastebin:pastebin_dev_password@localhost:5433/pastebin?sslmode=disable" \
S3_ACCESS_KEY=pastebin_minio S3_SECRET_KEY=pastebin_minio_password \
go run ./sweeper/cmd/sweeper
```
